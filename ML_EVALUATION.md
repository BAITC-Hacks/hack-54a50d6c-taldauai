добавлены проверка адресатов по исходным сегментам и проверка полноты длинных
транскриптов. На шести текстовых сценариях — 6/6 пройденных проверок против
2/6 у KazLLM с прежними инструкциями. Это сравнение конфигураций целиком,
а не изолированное сравнение весов. Отчёты: `examples/results/tasks-qwen-evaluation.json`
и `tasks-kazllm-baseline.json`.

Минутное синтетическое совещание `examples/audio/acceptance_mixed.wav`:
сквозной запуск с реальными моделями вернул 2/2 ожидаемых поручений с нужными
именами и датами; преобладающий голос совпал с эталоном в 4/4 реплик после
сопоставления меток. Это не стандартный DER и не доказательство точности
каждой границы. Отчёт — `examples/results/acceptance-evaluation.json`.
Говорящие и содержание задач остаются на проверку человеком.

Набор использовался при разработке, а не как независимая отложенная выборка.
Короткий исходный пример ниже по-прежнему демонстрирует ограничения.
Предоставленные участником более длинные записи проверяются отдельно локально;
их содержимое и результаты не публикуются в репозитории. Есть пропуски задач
и ошибки ответственных: перенос успеха синтетического примера на них не заявляется.
Инструкция воспроизведения: `ML_RUN.md`, раздел «Приёмка по ТЗ и экспорт».

Дополнительно проверено 26 unit-тестов. Валидация срока ищет подтверждение
в цитируемом ASR: перевод или пересказ срока заменяется буквальным фрагментом
с той же вычисленной датой и отправляется на проверку; без такого фрагмента
дата остаётся пустой. После изменения повторены 6/6 текстовых сценариев
и полный минутный аудиотест (2/2 задачи, 4/4 преобладающих голоса).
Адаптер backend `d28c107` принимает актуальный JSON; подробности и оставшиеся
проверки пользовательского цикла — [BACKEND_HANDOFF.md](BACKEND_HANDOFF.md).

Проведены два пилота дообучения CTC-слоя на небольшой выборке KSC2. Ни один
не улучшил Dev WER; исходные веса сохранены. На 31 естественном фрагменте
Tim2190 исходная модель получила WER 23,87%, CER 5,88% по буквальной разметке.
Протокол и ограничения: [TRAINING.md](TRAINING.md#фактический-запуск-23-сентября-2026).

Это проверка запуска на **пяти коротких синтетических фразах**, а не оценка
точности на живых совещаниях. Казахский голос macOS Aru озвучивал три смешанные
фразы и одну казахскую; Milena — одну русскую. В эталонах использован исходный
сценарий TTS, без независимой проверки произношения носителем языка. Ошибки
синтеза могут влиять на метрики.

| Записи | Mixed CTC CER | Mixed CTC WER | Whisper large-v3 CER | Whisper large-v3 WER |
|---|---:|---:|---:|---:|
| 3 смешанные | 8,81% | 35,00% | 15,09% | 45,00% |
| 1 казахская | 0,00% | 0,00% | 2,27% | 16,67% |
| 1 русская | 1,96% | 12,50% | 7,84% | 25,00% |

Метрики считаются по сумме ошибок / сумме эталонных символов или слов в группе.
Нормализация: нижний регистр, удаление пунктуации, выравнивание пробелов.
Буквы `ё`, `ұ`, `ү`, `і` и другие не заменяются похожими символами.

В этом замере специализированный ASR лучше обоих языковых контролей и
смешанной группы. Для первого эксперимента с живой записью предлагаем его,
сохраняя Whisper как переключаемый вариант. По этому малому набору нельзя
утверждать, что выбранная модель лучше на реальных совещаниях.

## Как повторить

Аудио: `examples/audio/*.wav`. Эталоны: `examples/shala_manifest.json`.
Результаты: `examples/results/*.json`. Все имена и поручения вымышлены.

```bash
TALDAU_ASR_ENGINE=mixed-ctc TALDAU_ASR_MODEL=models/mixed-stt \
  .venv/bin/python -m ml.evaluate examples/shala_manifest.json --output data/mixed-eval.json
TALDAU_ASR_ENGINE=whisper TALDAU_ASR_MODEL=models/faster-whisper-large-v3 \
  .venv/bin/python -m ml.evaluate examples/shala_manifest.json --output data/whisper-eval.json
```

Фикстуры уже включены: macOS для повторения оценки не требуется. Для их
пересоздания на macOS можно выполнить `python scripts/make_synthetic_audio.py`.

Запуск выполнен на macOS ARM64 CPU. Whisper: int8, beam=5, multilingual=True,
condition_on_previous_text=False. Mixed CTC: FP32, greedy, без KenLM. VAD:
Silero из faster-whisper. Время 2,37 с и 72,82 с в отчётах включает повторную
загрузку весов на каждом файле, поэтому это не оценка производительности
постоянно работающего сервиса.

Полный сценарий аудио → диаризация → KazLLM → JSON выполнен локально.
Результат: `examples/results/meeting_result.json`. На сценарии из двух поручений
получены три: подтверждение проверки договора выделено как отдельное поручение
с искажённым именем. Сроки завтра / пятница нормализованы в 24 / 25 сентября.
Все поручения помечены `needs_review: true`. Текстовая подсказка KazLLM
не устранила ключевые ошибки ASR. Это успешный запуск программы, но не
успешная проверка качества поручений.

```bash
TALDAU_ASR_ENGINE=mixed-ctc TALDAU_ASR_MODEL=models/mixed-stt \
TALDAU_DIARIZATION_MODEL=models/speaker-diarization-community-1 \
TALDAU_LLM_MODEL=taldau-kazllm TALDAU_KAZLLM_MODEL=taldau-kazllm \
  .venv/bin/python -m ml examples/audio/meeting_demo.wav \
  --started-at '2026-09-23T14:00:00+05:00' --num-speakers 2 --output data/meeting_result.json
```

На коротком двухголосном TTS-примере `examples/audio/meeting_demo.wav`
pyannote ошибается: без подсказки обнаруживает один голос, с `num_speakers=2`
разделяет запись на два кластера, но их границы не совпадают с истинной сменой
голосов. Этот результат не считается успешной проверкой диаризации.
Сценарий реплик хранится в `examples/meeting_manifest.json`.

Источники моделей: [Mixed STT](https://huggingface.co/alibiserikbay/kazakh-russian-mixed-stt)
(Apache-2.0; автор отмечает ограничения на дальнем микрофоне и совещаниях),
[Whisper large-v3 CT2](https://huggingface.co/Systran/faster-whisper-large-v3).

## Повторная проверка декодирования — 23 сентября, 14:34

Добавлен экспериментальный CTC prefix beam search (ширина 8) с Viterbi-
выравниванием выбранной последовательности по акустическим кадрам. Веса не
дообучались; словарь, KenLM и эталоны в распознавание не передавались.
Описание алгоритма: [Awni Hannun, Sequence Modeling with CTC](https://distill.pub/2017/ctc/).

| Набор | Greedy CER / WER | Beam 8 CER / WER |
|---|---|---|
| 3 смешанные фразы | 8,81% / 35,00% | 8,18% / 35,00% |
| Казахский контроль | 0,00% / 0,00% | 0,00% / 0,00% |
| Русский контроль | 1,96% / 12,50% | 1,96% / 12,50% |
| Синтетическое совещание (23 слова) | 2,92% / 13,04% | 2,34% / 8,70% |

На совещании ошибок в словах стало 2 вместо 3: модель разделила «яданир»
на «я данир», но имя всё ещё написано неверно. На смешанных фразах исправлен
лишь один символ из 159. Это небольшое улучшение на тех же синтетических
примерах, которые использовались при разработке, а не независимая проверка.
Время в JSON включает загрузку весов и прогрев; по нему нельзя сравнивать скорость.

Результаты: `examples/results/mixed-ctc-beam-evaluation.json`,
`meeting-asr-greedy.json`, `meeting-asr-beam.json`.

```bash
TALDAU_ASR_ENGINE=mixed-ctc TALDAU_ASR_MODEL=models/mixed-stt TALDAU_CTC_BEAM_SIZE=8 \
  .venv/bin/python -m ml.evaluate examples/shala_manifest.json --output data/beam-eval.json
TALDAU_ASR_ENGINE=mixed-ctc TALDAU_ASR_MODEL=models/mixed-stt TALDAU_CTC_BEAM_SIZE=8 \
  .venv/bin/python -m ml.evaluate examples/meeting_asr_manifest.json --output data/meeting-beam.json
# Для сравнения повторите с TALDAU_CTC_BEAM_SIZE=1.
```

Сквозной запуск beam → pyannote → KazLLM сохранён в
`examples/results/meeting-beam-result.json`. Остались три поручения вместо двух,
ошибки диаризации и неверные исполнители; у поручения про отчёт исполнитель
даже ухудшился с Айданы до Данияра. Поэтому **beam остаётся опциональным**,
а улучшение ASR не заявляется как улучшение всего протокола. Все задачи
с неподтверждённой связью имени и голоса требуют проверки.

Whisper с подсказками «Айдана, Данияр, договор, замечания, отчёт» исправил имя
Данияр, но пропустил казахские реплики: WER 65,22% без подсказок и 56,52% с ними.
Подсказки взяты из известного сценария, поэтому это проверка функции,
а не независимый замер. Результат: `examples/results/whisper-hotwords-comparison.json`.
Whisper не заменяет Mixed CTC по умолчанию.

Проверено 17 unit-тестов, включая сравнение beam search и выравнивания
с полным перебором 81 пути на каждом из 15 маленьких случайных примеров.
Отдельный запуск на двухсекундном WebM с тишиной вернул пустой протокол
с предупреждением без вызова диаризации и LLM. Новые регрессионные проверки
покрывают пересечения голосов, паузы, точные дубли, неподтверждённые имена
и некорректный ответ необязательной коррекции.
