# Готовность к тестированию и сдаче

Основание: ТЗ и инструкция участников, предоставленные командой 23.09.2026. Баллы ниже — веса критериев, не прогноз оценки жюри.

## Сверка с кейсом

| Требование | Реализация и подтверждение | Ограничение |
|---|---|---|
| Русская, казахская, смешанная речь | Локальный Mixed CTC; реальная обработка `acceptance_mixed.wav`, отчёты `ML_EVALUATION.md`, `ACCEPTANCE.md` | Ошибки ASR возможны; синтетический тест не доказывает качество любой записи |
| Диаризация и ответственный | pyannote, идентификаторы говорящих, связь поручения с участником; секретарь уточняет имена | Не является биометрической идентификацией; неоднозначные фрагменты отмечаются |
| Поручение, ответственный, срок | Локальный Qwen/Ollama, извлечение из транскрипта, ссылки на исходные сегменты | Нужна проверка; пропущенное поручение можно добавить вручную |
| Саммари и транскрипт | Сохраняются в PostgreSQL, показываются в карточке | Саммари может быть кратким перечнем найденных поручений |
| Экспорт PDF/DOCX | Реальный DOCX после проверки поручений | PDF нет; в обязательном минимуме предусмотрен PDF/DOCX |
| Уведомление о записи | Обязательное подтверждение в форме загрузки/начала записи | Секретарь фактически уведомляет участников; флажок не рассылает им сообщения |
| Запись встречи | Загрузка аудио/видео, запись микрофона; новый `/live` смешивает микрофон и звук вкладки | Выбор вкладки и передача звука зависят от браузера; это не бот-участник Teams/Zoom/Meet и не streaming ASR |
| Автоматические напоминания | Фоновый планировщик, локальный журнал, индикатор непрочитанных, приближающийся срок и просрочка | Общий журнал, без персональных аккаунтов и внешней доставки; сценарий 2 демонстрируется внутри приложения |
| Локальная обработка | Модели и Ollama на машине, API/БД на loopback, без внешних API для аудио/текста | Модели и зависимости нужно получить заранее; промышленная защита и авторизация не реализованы |
| Контроль исполнения | Реестр, фильтры, выполнено/в работе/просрочено, ручная срочность | СЭД, автоматическая рассылка выдержек и классификация направлений не реализованы |

По формулировке обязательного минимума путь «запись → протокол DOCX» покрыт. Возможность присоединения ботом к платформам перечислена среди входов, но не выделена в обязательном минимуме: подтвердите у ментора, что приёмка по записи достаточна. Не заявляйте реализованную интеграцию Teams/Zoom/Meet.

- **Работоспособность, 25:** показать настоящий ML, исправление ошибки, внешнего ответственного, ручное поручение, подтверждение и DOCX. Не демонстрировать статические HTML-макеты вместо рабочего приложения.
- **Техническая реализация, 25:** показать контракт ML, PostgreSQL, `failed`, миграции, проверку версий при правках, автоматические напоминания. Различать тесты с подменённым ML и реальный браузерный прогон.
- **README, 25:** повторить команды в чистой копии; установить веса по `ML_RUN.md`, проверить `ml.doctor`, запустить миграции/API/UI. Без заранее доступных весов полноценная проверка с одного GitHub-клона невозможна.
- **Ценность, 15:** продемонстрировать путь секретаря и контроль поручений. Не обещать измеренную экономию времени без измерений.
- **Развитие, 10:** назвать персональные роли/напоминания, устойчивую очередь обработки, улучшение живой смешанной речи и интеграции как следующий этап.

## Текст для подачи

**Название:** TaldauAI — локальное автопротоколирование совещаний.

**Описание:** Прототип для секретаря и руководителя: русская, казахская и смешанная речь преобразуется локальными моделями в транскрипт, саммари и поручения с ответственными и сроками. Система различает говорящих, позволяет исправлять и добавлять поручения, требует ручной проверки перед экспортом DOCX, сохраняет результат в PostgreSQL и автоматически формирует напоминания внутри приложения. Поддерживаются загрузка записи и запись через браузер. Аудио и текст не отправляются во внешние облачные API. Ограничения и воспроизводимая проверка описаны в README.
