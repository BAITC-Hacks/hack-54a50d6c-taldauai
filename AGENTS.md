# AGENTS.md: правила работы для AI-агентов (HackAlem AI, команда TaldauAI)

Полные правила хакатона: HACKATHON_PLAN.md и положение. Соревновательная часть 13:00–18:00 (Астана). В 18:00 репозиторий замораживается, изменения после не учитываются. Проверяется ветка main.

## Ветки
- Каждый участник работает в своей ветке `<имя>/<зона>`, например `almaz/backend`.
- Перед началом работы проверь текущую ветку (`git branch --show-current`). Если это main, не коммить туда фичи: предложи переключиться в ветку участника.
- Не делай force push, rebase или amend уже запушенных коммитов. Не удаляй чужие ветки.

## Коммиты
- Коммить после каждой завершённой логической части, минимум раз в 30–40 минут.
- Формат: `feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`, на английском.
- После коммита сразу `git push`.

## Синхронизация с main (обязательно каждый час)
Когда пользователь пишет «sync» или прошло больше часа с последнего мержа, выполни:
1. Закоммить и запушь текущие изменения в своей ветке.
2. `git switch main && git pull`
3. `git merge <своя-ветка>`; при конфликте остановись и покажи конфликт пользователю, не решай его молча.
4. Убедись, что проект запускается, затем `git push`.
5. `git switch <своя-ветка> && git merge main && git push`
После 17:15 работа ведётся только в main: финальные правки и проверка запуска.

## Секреты
- Никогда не хардкодь API-ключи и токены. Только переменные окружения из `.env`.
- `.env` в `.gitignore`. Поддерживай актуальный `.env.example` без реальных значений.

## README.md
Держи актуальным после любых изменений, влияющих на установку или запуск. Разделы: описание и назначение; архитектура; технологии; зависимости и системные требования; установка; переменные окружения; запуск; как проверить основной сценарий (пошагово); использованные сторонние компоненты (open-source, модели, датасеты).
Если проект не запускается по README, команду снимают без права исправить.
