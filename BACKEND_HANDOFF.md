# Передача ML backend-разработчику

> Исторический отчёт об адаптере `d28c107`. Актуальные запуск, defaults и
> разрешение путей описаны в [README](README.md) и [инструкциях](docs/SETUP_MACOS.md).
> Нынешний backend по умолчанию использует `local_ml`; относительные пути
> ASR/диаризации разрешаются от корня репозитория. Ограничения старой версии
> ниже сохранены как контекст проверки, а не инструкция текущего запуска.

Проверено 23 сентября 2026 с `origin/almaz/backend`, коммит `d28c107`.
Модуль `adapt_ml_result` вызван на настоящих сохранённых результатах двух
предоставленных MP3 и публичного синтетического совещания. Все три результата
приняты; число задач, ссылки на реплики, сроки, предупреждения и `needs_review`
сохранены. Это проверка адаптера, а не HTTP/БД/браузера.

## Подключение

Использовать актуальный `ml` из `kashyyn/ml` вместе с кодом backend своей ветки.
Установить `requirements-ml.txt` в окружение процесса backend, подготовить веса
по [ML_RUN.md](ML_RUN.md). В окружении backend задать:

```dotenv
ASR_BACKEND=local_ml
LLM_BACKEND=local_ml
TALDAU_ASR_ENGINE=mixed-ctc
TALDAU_ASR_MODEL=/absolute/path/TaldauAI/models/mixed-stt
TALDAU_DIARIZATION_MODEL=/absolute/path/TaldauAI/models/speaker-diarization-community-1
TALDAU_LLM_MODEL=qwen2.5:7b
TALDAU_OLLAMA_URL=http://127.0.0.1:11434
TALDAU_DEVICE=cpu
```

Удалить `TALDAU_ML_RESULT_FIXTURE` для реальной обработки. Не включать
`TALDAU_KAZLLM_MODEL`, если локальные веса не подготовлены. Относительные пути
зависят от рабочей папки процесса; абсолютные пути избегают этой ошибки.
В указанном коммите backend режим по умолчанию `stub`: он возвращает
демонстрационный ответ и не проверяет качество загруженной записи.
Свой `DATABASE_URL` тоже необходимо задать явно.

## Семантика JSON

- Функция возвращает черновик. `completed` означает завершение обработки,
  а не подтверждение всех фактов человеком.
- `display_name` подтверждается человеком; `suggested_name` можно показывать
  только как подсказку. Диаризация не идентифицирует личность по голосу.
- Исполнитель может отсутствовать на совещании: имя есть, `assignee_speaker_id`
  отсутствует. Не назначать вместо него автора реплики.
- `due_date=null` допустим при неоднозначном или отсутствующем сроке. Нужно
  сохранить исходное `due_text`, дать человеку уточнить его и не включать
  такое поручение в автоматическую рассылку по срокам.
- `assignment_quote` необязателен; `source_segment_ids` остаются источником
  проверки. Исходный текст ASR сохраняется даже при наличии `suggested_text`.
- При исключении ML backend должен выставить `failed`, сохранить понятную
  ошибку и разрешить повторную обработку.

## Что осталось проверить вместе перед сдачей

1. Загрузка MP3/WebM и уведомление о записи → реальная обработка → просмотр
   результата → исправление имени/срока → подтверждение → скачивание DOCX.
2. Очередь обработки: одновременные тяжёлые модели могут исчерпать память.
3. В текущем backend подтверждение требует заполненного срока. Для задач без
   срока нужен понятный путь ручного уточнения, без выдуманной даты.
4. Автоматические напоминания: ручной маршрут `remind` не подтверждает работу
   фонового расписания и доставки. Этот сценарий отдельно ещё не проверен.
5. Отключить демонстрационные фикстуры и проверить запуск по README на чистом
   окружении. DOCX удовлетворяет варианту экспорта PDF/DOCX; PDF в ML нет.

Реальные аудио, транскрипты и протоколы не публиковать. Тестовые данные для
публичной демонстрации: `examples/audio/acceptance_mixed.wav` и соответствующий
эталон. Синтетический тест небольшой и использовался при разработке.
